# 前端优化报告 · 2026-10-13

范围：`apps/web` 全部页面（速闻、热榜、简报、橘鸦、研究者、我的、搜索、分类/来源、阅读页），以及与前端体验直接相关的 AI 配置和 Web 进程稳定性。品牌视觉（Signal Press：纸色、墨色、黄色信号、直角硬边）保持不变，在其内部做减法和重排。

## 1. 诊断（改版前，线上实测）

测量方式：Playwright + Chrome 访问 `https://hotai.yeuxark.com`，桌面 1440×900 / 手机 390×844，亮/暗两种主题。

### P0 · 缺陷

| # | 问题 | 证据 | 根因 |
|---|---|---|---|
| 1 | **首页加载后自动下滚 320–366px** | 4 次加载 3 次复现；CLS 0.30–0.34（> 0.25 即"差"） | `NookFeed` 流式重排时，"阅读连续性"逻辑把首屏顶部的卡片当作阅读锚点，重排后滚动页面去追它 |
| 2 | **AI 摘要 / 简报 / 问答全部失效** | `/api/health`：`success 0 / failed 759 / retry 242 / pending 1201`，简报从未生成 | 旧中转站（HF Space）每次返回 `500 Database pool not initialized` |
| 3 | **React hydration 报错 #418**（搜索页） | 浏览器控制台 | 超过 7 天的日期用 `toLocaleDateString()`，服务器（UTC）与浏览器（本地时区）输出不同 |
| 4 | **Web 进程每 1–4 天被 PM2 强制重启** | `pm2.log`：`exceeds --max-memory-restart (548MB > 512MB)` 共 10 次 | V8 按 2.4G 主机内存设定堆上限、回收偏懒，进程常驻内存越过 PM2 的 512M 线（DOMPurify/jsdom 已排除：真实请求节奏下 1500 次净化后堆稳定在 37MB） |

### P1 · 体验与视觉

- **首屏浪费**：顶栏两行 120px；首页标题区（`LIVE · AI 信号编辑部` + 92px 的 `00/综合` + 三格统计控制台）占 440px，手机上第一条新闻在约 880px，落在首屏之外。
- **噪音过多**：导航 `01–06`、频道 `01–09`、卡片 `/01…/24`、`LEAD / 01` 贴纸（手机上还压住了元信息）、每张卡片常驻 3px 边框 + 5px 硬阴影。
- **卡片网格留白**：等高网格中无图卡片被有图卡片撑高，出现大片空白。
- **内容脏数据直出**：热榜摘要显示 `Article URL: … Comments URL: … Points: 335 # Comments: 169`；谷歌新闻标题带 ` - 第一财经` 后缀，摘要是一串相关标题拼接；来源标签显示"国际/商业"（谷歌新闻栏目名）而不是真正的媒体。
- **热榜**：每条文章一张重边框卡片 + 一排 2px 边框标签，信息层级平；裸数字 `6.4` 没有说明；"今日脉搏"在没有简报时仍放一个指向空页面的按钮，手机上把榜单推到首屏外。
- **中文标题用重衬线（Noto Serif SC 900）**，新闻列表阅读压迫感强；英文正文落到中文衬线字体上时弯引号变全角（`company’ s`）。
- 简报页要点链接中英混写（`站内阅读 · Read on Hot AI`）；橘鸦页头卡片无内边距，文字贴边；研究者页 favicon 失败时显示破图。
- 对比度：`--fade #8d93a5` 在卡片底色上约 3:1，小字号不达 WCAG AA。

### P2 · 性能

- 字体来自 `fonts.googleapis.com` 的**阻塞渲染样式表**（4 个家族，含 Noto Serif SC），首访 FCP 实测 8.5s；在中国大陆网络下 Google 字体常被阻断或极慢。
- body 背景三层渐变 + `background-attachment: fixed`，滚动时整页重绘。

### P3 · 代码健康

- `globals.css`（2126 行）+ `signal.css`（1092 行）两层互相覆盖：同一选择器两处定义（如 `.kz-nook-list` 先 columns 后 grid）、大量与亮色完全相同的 `html[data-theme="dark"]` 重复规则。
- Tailwind 配置维护一套与 CSS 变量重复的色板，组件里实际只用到 6 个工具类。

## 2. 实施内容

### 修复

| 问题 | 改动 |
|---|---|
| 首页自动下滚 | `NookFeed.publish`：只有读者已滚进列表内部（列表顶部在视口之上）时才做锚点保持；在页面顶部时重排就地完成 |
| AI 失效 | 切到 `grok.yeuxark.com` 的 grok-4.6（Anthropic `/v1/messages` 兼容）。实测批量摘要 10/10、单篇、简报均正常。该中转站对**不带推理内容的流式请求**返回 `503 上游响应缺少推理`（5/5 必现），开启 thinking 后 5/5 成功 → 新增 `AI_STREAM_THINKING_BUDGET`（默认 0 不影响直连 Anthropic；生产设为 1024），`/api/ask` 的配额预留同步计入思考预算 |
| hydration #418 | `timeAgo` 的日期格式固定时区（中文 Asia/Shanghai，英文 UTC）；新增 `<TimeAgo>` 统一渲染 |
| 内存重启 | `ecosystem.config.js` 为 hotai-web 设置 `NODE_OPTIONS=--max-old-space-size=320`，让 GC 在 512M 重启线之前工作 |
| 脏摘要 / 谷歌新闻标题 | 新增 `lib/story-text.ts`：清除 HN 链接/分数样板、纯标点或与标题重复的摘要；拆出谷歌新闻标题后缀作为真实来源，丢弃相关标题拼接。仅作用于展示层，存储不变 |
| favicon 破图 | 新增 `<SiteIcon>`：加载失败（含 Google 服务被墙）时显示首字母方块 |

### 视觉与信息架构（Signal Press v2）

- **顶栏**：桌面单行（logo · 栏目 · 搜索 · 主题 · 语言），60px；手机两行 96px，搜索收进图标按钮，点开后浮层展开。栏目改为文字 + 黄色下划线，去掉编号与标语。
- **速闻首页**：标题区压缩为"标题 + 一句说明 + 一行状态（在线源 / 条数 / 异常 / 刷新）"；频道条去编号，手机可横向滑动。
  - 头条：通栏，左侧黄色信号条，有图时图左文右；去掉 `LEAD / 01` 贴纸。
  - 其余：两列（手机一列）**横向缩略图卡片**，标题 3 行、摘要 2 行截断，行高可控，不再有大片空白。
  - 常驻硬阴影只留给头条；其他卡片悬停时才浮起。
- **热榜 / 搜索 / 分类 / 来源 / 订阅时间线**：统一为"面板 + 分隔线"的列表行；前三名黄底名次，名次列等宽对齐；元信息改为纯文本（来源 · 域名 ↗ · 时间 · `热度 6.4`（带解释）· 转载 · 类型 · `#主题`）。
- **今日脉搏**：桌面左侧吸顶；没有简报时给出状态说明而非空按钮；手机上只保留头条、入口和三项统计；抓取时间中文显示北京时间。
- **阅读页**：标题 26–38px 无衬线；AI 摘要用左侧黄条区块；正文英文用 Source Serif 4、中文用系统宋体（Windows 回落雅黑而非 SimSun）。
- 色彩：`--fade` 加深到 `#676d82`（AA 达标）；暗色卡片 `#131622`，蓝色硬阴影仅用于头条/悬停；浏览器 `theme-color` 与顶栏同色。
- 文案：简报链接随语言切换；"继续读取下一组"→"加载更多"；橘鸦页头补内边距。

### 性能

- 字体改用 `next/font` **构建时自托管**：IBM Plex Sans（可变字重）、IBM Plex Mono、Archivo Black、Source Serif 4（阅读页按需），浏览器不再请求 Google。中文全部用系统字体——试过自托管 Noto Serif SC，会给每个页面的 CSS 增加约 200 条 `@font-face`（gzip 后 63KB），已放弃。
- 全站样式合并为单一 `globals.css`：构建产物 48.5KB / gzip 9.7KB，字体文件合计 444KB 且按需加载。
- 背景改为单层点阵、不再 `fixed`。

## 5. 后续建议（未在本轮实施）

1. **在 fetcher 入库时清洗摘要**（HN 样板等），让 RSS/JSON Feed 输出也干净；目前只在展示层处理。
2. **favicon 服务端代理 + 缓存**：Google favicon 服务在大陆不可达，现在只能显示首字母兜底。需要做 SSRF 防护。
3. **整站动态渲染**：根布局读取语言 cookie，导致所有页面都无法被 CDN 缓存。可考虑语言放进 URL 或纯客户端切换，让速闻外壳、研究者页等可静态化。
4. **观察内存**：若设置堆上限后仍持续上涨，抓 heap snapshot 定位（Next 缓存、`feed-cache` 等）。
5. **简报语言**：当前 digest prompt 输出英文标题，中文界面下可改为双语字段。
6. 删除无引用组件 `CategoryNav`；手机端频道条可考虑吸顶。

### 6.3 首页流式重排（第一轮遗留 #7）

新列表更紧凑，首屏同时可见的条目更多，编辑排序在来源陆续到达时的换位更明显：重做后、修复前实测手机 CLS 一次达到 0.30。

改法：综合/要闻频道在排序拿到足够来源（≥8 个在线源且含一个编辑锚点源）之前保持骨架屏，之后一次性按最终顺序渲染，后续到达的来源只影响可见页之下；最长等待 2.5 秒。线上服务端有源缓存，整条流在首个事件后约 0.4–0.6 秒内到齐，排序稳定约在首个事件后 0.2–0.3 秒，因此首屏出现时间只推迟约 0.3 秒（按流事件时间推算，未做 A/B 实测）。
