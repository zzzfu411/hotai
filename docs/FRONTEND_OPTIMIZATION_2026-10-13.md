# 前端优化报告 · 2026-10-13

范围：`apps/web` 全部页面（速闻、热榜、简报、橘鸦、研究者、我的、搜索、分类/来源、阅读页），以及与前端体验直接相关的 AI 配置和 Web 进程稳定性。品牌视觉（Signal Press：纸色、墨色、黄色信号、直角硬边）保持不变，在其内部做减法和重排。

## 1. 诊断（改版前，线上实测）

测量方式：Playwright + Chrome 访问 `https://hotai.yeuxark.com`，桌面 1440×900 / 手机 390×844，亮/暗两种主题。

### P0 · 缺陷

| # | 问题 | 证据 | 根因 |
|---|---|---|---|
| 1 | **首页加载后自动下滚 320–366px** | 4 次加载 3 次复现；CLS 0.30–0.34（> 0.25 即"差"） | `NookFeed` 流式重排时，"阅读连续性"逻辑把首屏顶部的卡片当作阅读锚点，重排后滚动页面去追它 |
| 2 | **AI 摘要 / 简报 / 问答全部失效** | `/api/health`：`success 0 / failed 759 / retry 242 / pending 1201`，简报从未生成 | 旧中转站（HF Space）每次返回 `500 Database pool not initialized` |
| 3 | **React hydration 报错 #418**（搜索页） | 浏览器控制台 | 超过 7 天的日期用 `toLocaleDateString()`，服务器（UTC）与浏览器（本地时区）输出不同 |
| 4 | **Web 进程每 1–4 天被 PM2 强制重启** | `pm2.log`：`exceeds --max-memory-restart (548MB > 512MB)` 共 10 次 | V8 按 2.4G 主机内存设定堆上限、回收偏懒，进程常驻内存越过 PM2 的 512M 线（DOMPurify/jsdom 已排除：真实请求节奏下 1500 次净化后堆稳定在 37MB） |

### P1 · 体验与视觉

- **首屏浪费**：顶栏两行 120px；首页标题区（`LIVE · AI 信号编辑部` + 92px 的 `00/综合` + 三格统计控制台）占 440px，手机上第一条新闻在约 880px，落在首屏之外。
- **噪音过多**：导航 `01–06`、频道 `01–09`、卡片 `/01…/24`、`LEAD / 01` 贴纸（手机上还压住了元信息）、每张卡片常驻 3px 边框 + 5px 硬阴影。
- **卡片网格留白**：等高网格中无图卡片被有图卡片撑高，出现大片空白。
- **内容脏数据直出**：热榜摘要显示 `Article URL: … Comments URL: … Points: 335 # Comments: 169`；谷歌新闻标题带 ` - 第一财经` 后缀，摘要是一串相关标题拼接；来源标签显示"国际/商业"（谷歌新闻栏目名）而不是真正的媒体。
- **热榜**：每条文章一张重边框卡片 + 一排 2px 边框标签，信息层级平；裸数字 `6.4` 没有说明；"今日脉搏"在没有简报时仍放一个指向空页面的按钮，手机上把榜单推到首屏外。
- **中文标题用重衬线（Noto Serif SC 900）**，新闻列表阅读压迫感强；英文正文落到中文衬线字体上时弯引号变全角（`company’ s`）。
- 简报页要点链接中英混写（`站内阅读 · Read on Hot AI`）；橘鸦页头卡片无内边距，文字贴边；研究者页 favicon 失败时显示破图。
- 对比度：`--fade #8d93a5` 在卡片底色上约 3:1，小字号不达 WCAG AA。

### P2 · 性能

- 字体来自 `fonts.googleapis.com` 的**阻塞渲染样式表**（4 个家族，含 Noto Serif SC），首访 FCP 实测 8.5s；在中国大陆网络下 Google 字体常被阻断或极慢。
- body 背景三层渐变 + `background-attachment: fixed`，滚动时整页重绘。

### P3 · 代码健康

- `globals.css`（2126 行）+ `signal.css`（1092 行）两层互相覆盖：同一选择器两处定义（如 `.kz-nook-list` 先 columns 后 grid）、大量与亮色完全相同的 `html[data-theme="dark"]` 重复规则。
- Tailwind 配置维护一套与 CSS 变量重复的色板，组件里实际只用到 6 个工具类。

### 6.3 首页流式重排（第一轮遗留 #7）

新列表更紧凑，首屏同时可见的条目更多，编辑排序在来源陆续到达时的换位更明显：重做后、修复前实测手机 CLS 一次达到 0.30。

改法：综合/要闻频道在排序拿到足够来源（≥8 个在线源且含一个编辑锚点源）之前保持骨架屏，之后一次性按最终顺序渲染，后续到达的来源只影响可见页之下；最长等待 2.5 秒。线上服务端有源缓存，整条流在首个事件后约 0.4–0.6 秒内到齐，排序稳定约在首个事件后 0.2–0.3 秒，因此首屏出现时间只推迟约 0.3 秒（按流事件时间推算，未做 A/B 实测）。

## 9. 第五轮：响应速度、暗色配色、触控反馈（2026-10-14，线上 6d80536）

### 9.1 诊断（线上 167e841，本机 Chrome 访问）

- **速闻首屏等 5 秒**：手机上第一条新闻在导航后约 5.1 s 才出现。顺序是 HTML（1.3 s）→ CSS/JS（3.8 s）→ 水合 → `POST /api/catalog/pull`（4.7 s）→ 渲染。服务器渲染本身只要 20–200 ms，慢在串行的网络往返。
- **满屏预取**：每条可见新闻、来源名、标签链接都会触发一次 `?_rsc` 预取。这些页面都是按请求渲染的，预取拿不到页面内容，只是在点击时和真正的请求抢连接。
- **favicon 卡住加载**：热榜每条新闻都请求 Google favicon 服务。在无法访问 Google 的网络里，每个请求都要等到超时，浏览器一直显示加载中（热榜 `load` 事件 4.3 s）。
- **暗色刺眼**：近黑底配近白粗标题，前三名、简报序号是实心亮黄块，选中频道是白色胶囊，主按钮是大块白色，「站内阅读」标签发橄榄色。
- **主题图标错位**：服务器总是渲染月亮图标，暗色下要等水合（约 3 s）后才变成太阳。

### 9.2 改动

- **速闻首屏由服务器渲染**（`lib/catalog-snapshot.ts`）：只读进程内 feed 缓存，不等网络、不查数据库、不写 `Article`。只渲染一页（24 条，摘要截到 120 字），浏览器随后照常拉取完整时间线，替换时不移动屏幕上的条目。综合/要闻沿用流式的「等到足够来源再定序」规则，缓存不够时退回原来的骨架屏 + 流式加载。页面渲染只在后台刷新已缓存但过期的源，不会对从未抓过的源发起冷抓取（冷抓取仍走有限流的 `/api/catalog/pull`）。合并与排序逻辑移到 `lib/nook-merge.ts`，前后端共用。
- **点按立即有反馈**：频道按钮点下即高亮，旧列表变淡直到新频道到达；新闻行、顶栏栏目、翻页按钮在加载期间显示一条移动的强调色细线，标题变淡（`useLinkStatus`）。
- **试过并放弃 `loading.tsx` 骨架屏**：骨架屏能在点按后约 20 ms 出现，但 React 会把真实内容压在骨架屏后至少 300 ms。同样条件下实测内容反而更晚出现（30 ms 延迟：热榜 871 ms 对比 137 ms，文章 846 ms 对比 121 ms），所以改用上面的行内反馈。
- **只预取每个列表的第一条**：新闻、来源、标签链接不再随可见即预取；每个列表第一条做完整预取，顺带加载阅读页代码，其余条目共用。
- **favicon 先显示首字母**：页面加载完成后用一张图片探测 Google favicon 服务，能访问才换成真图标，结果在本次会话内记住。访问不了时整页只有这一个请求。
- **主题/密度图标**：两个图标都随 HTML 下发，由 `<html>` 上的类决定显示哪个，首次绘制就正确。
- **暗色配色**：底色抬到石墨灰 `#121418`，正文稍暗，标题字重降一级（列表 600→500，大标题 700→600）。黄色在暗色下改为淡色底：选中频道/筛选标签、前三名、简报序号、「站内阅读」标签、稍后读徽标、引用编号都用琥珀色淡底加浅琥珀字，不再用实心亮黄块。主按钮从白色调暗到 `#d5d9e0`，缩略图和正文图片亮度降到 88%，悬停时恢复。所有文字色在底色和卡片色上都满足 WCAG AA（最暗的 `--fade` 在卡片色上为 5.24:1）。
- **阅读舒适度**：大标题平衡换行，摘要和正文避免末行只剩一个字，触屏点按新闻行有底色反馈，头条图片优先加载。

## 10. 第六轮：信息密度、读者工具、页面整理（2026-10-15）

### 10.1 诊断（线上 6d80536）

- **速闻头条留白**：桌面头条占满一整行，综合频道的头条多来自 Google News（没有摘要和图片），右侧大半行是空白。
- **标题乱码**：部分 Feed 把文字转义了两次（`&amp;#8217;`），XML 解析后仍留下 `&#8217;`，如 The Verge 标题里的 `users&#8217; data`。
- **摘要残渣**：首屏快照把摘要截到 120 字，Hacker News 的「Article URL / Comments URL / Points」页脚被截断后剩下一个「P…」；少数派摘要末尾带「…查看全文」。
- **状态栏吓人**：「2 异常」红字对读者没有用，只是让页面看起来坏了。
- **简报每天早上是空的**：简报按 UTC 日生成，北京时间 08:00 换日后要等当天入库满 5 篇，这段时间 `/digest` 只有「尚未发布」和一条「今日最热」；热榜侧栏同样只有一句说明。

- **文章页**：时间是 UTC，中英文摘要分成两个大块，话题标签是一排排胶囊，手机上占三行。

### 10.2 改动

- **速闻头版**（宽屏 ≥ 900 px、紧凑排版）：头条占左侧三分之二，右侧竖排接下来 3 条，中间一条细分隔线，之后照旧两栏。没有摘要也没有图片的头条只配 2 条侧栏，避免标题下方留一大块空白。六列网格让两种布局共用一个列表，DOM 顺序仍是阅读顺序。手机和舒适排版不变。
- **Feed 文本解码**：`parse-remote-feed` 对标题和摘要再解一层 HTML 实体（数字实体和常用命名实体），标题不去标签，`<canvas>` 这类文字保留。
- **摘要清理**：从 HN 页脚开头整段截掉（包括被截断的页脚）；去掉「查看全文 / 阅读全文 / Continue reading / […]」结尾，正常截断的「…」保留。
- **状态栏**：去掉红色「N 异常」，来源有问题时圆点变成琥珀色，数量在悬停提示里。
