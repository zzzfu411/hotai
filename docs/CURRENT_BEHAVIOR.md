# Hot AI 当前行为合同

校准日期：2026-09-05。本文描述当前实现；历史设计稿保留决策背景，发生冲突时以本文和运行代码为准。

## 产品与数据

Hot AI 是多源速闻阅读器，包含独立的 AI 入库热榜、简报和问答模块。综合速闻覆盖通用新闻；AI 模块聚焦研究、产业、开源和媒体。无账号、无个性化推荐。

| 模块 | 数据来源和存储 | 排序 / 边界 |
|---|---|---|
| 速闻 `/` | 服务端代理内置目录的 RSS/Atom/JSON Feed；内存缓存，不写 Article | 综合与头条采用编辑信号排序，其他频道按最新；来源集合和内容总量有界 |
| 热榜 `/hot` | PostgreSQL Article | 默认最近 14 天，重要度综合排名，展示 top 50 |
| 分类、单源 | 同一 Article 数据集 | 发布时间、ID 稳定次序；每页 80，最多 1000 页 |
| 搜索 | Article 标题、摘要、主题；不搜索实时速闻和自定义订阅 | 至少 2 字、最多 80 字；热度或最新；每页 60，显示本页数量 |
| 简报、Ask | 当日 / 过去 48 小时的入库语料 | UTC 编辑日，北京时间 08:00 换日；AI 可选，空语料不调用模型 |
| 橘鸦 | 外部 RSS 正文 | 原文展示，不入 Article；正文保持中文 |
| 研究者目录 | CuratedBlog 编辑数据 | 长期保留，独立于文章保留期 |
| 我的 | 浏览器订阅与阅读快照 | 无服务器用户状态；最多 400 条阅读标记，单个 OPML 文件最多 1 MB |

Article 默认保留 14 天，可由 `ARTICLE_RETENTION_DAYS` 配置。过期后站内 ID 可能不存在；新版稍后读保留标题和原文 URL，仍可访问原站。老版数字书签在下一次成功打开文章时补全快照，已经过期的老 ID 无法凭空恢复原文。清理浏览器会删除本机记录；OPML 备份仅包含订阅源。

## 交互约定

- 速闻进入阅读页再返回时，保留已展开数量与锚点位置；主动刷新可应用新的排序，并重新从首组展示。
- 实时 API 输出 `stale`、`fetchedAt`；缓存可读与来源在线分别展示。请求失败不把尚未请求的来源算作失败。
- 内部热榜目录条目携带受信任的 `articleId` 和原文 URL，直接进入 `/a/id`；远程条目进入 `/r`。我的订阅使用同一阅读器。
- 稍后读和已读互斥。浏览器写入失败会显示“仅本次会话有效”，不会虚报持久保存。
- 搜索提交、排序和分页以 URL 为准；更换关键词或排序重置页码。
- 界面语言由 `hotai-lang` cookie 供服务器和客户端共同读取，兼容旧本机偏好。内容语言不冒充翻译。
- 手机页头默认收起搜索，按钮可展开并聚焦；当前场景随导航、窗口缩放保持可见。

## 可靠性与成本

公开抓取接口继续使用 PostgreSQL 共享限流。DB 不可用时不启动新的抓取；速闻可以返回已有、仍在 45 分钟窗口内的安全快照。缓存是进程内的，重启或切换实例会冷启动。新鲜 TTL 为 8 分钟，失败重试冷却为 2 分钟；陈旧窗口不会被连续失败无限延长。

Ask 缓存键包含标准化问题、模型、提示版本、UTC 日期以及当前语料内容；TTL 是最长复用时间，不能跨语料版本复用。回答流必须有明确 `done`，断流保留部分文本并提示未完成。配额与跨进程并发保护保持失败关闭。

Digest 的网络调用期间续租，最终数据库事务在与租约认领相同的锁下验证 owner、状态和过期时间。旧 owner 不得提交。Web 首访与 fetcher 共享同一协议。正文 enrichment 保留原有重试/租约机制。

来源连续失败达到 `SOURCE_FAIL_THRESHOLD`（默认 5）后设置 `autoPausedUntil`，默认 `SOURCE_RETRY_MINUTES=60` 后自动探测；成功清零。`enabled=false` 仅表示人工停用，不会自动重启。迁移前已经停用的来源无法判断停用原因，保留原状态，由运营核实后恢复。

## 运维与发布

`/api/live` 只测 Web 存活；`/api/health` 的 HTTP 状态仍代表 DB 和入库管线就绪，同时返回 `catalog` 独立状态及陈旧、AI、Digest 等告警。`catalog.scope=process`，冷缓存是 `unknown`；不能将入库管线 200 当成所有实时源可用。`/api/metrics` 导出低基数聚合指标并保留 token 鉴权。

`pnpm smoke:catalog` 通过正常限流探测指定实时源，不调用 AI。默认 `hn,bbc-tech`，至少一个新鲜且非空的来源才通过。生产运行前设置 `SMOKE_BASE_URL`；支持用 `SMOKE_CATALOG_IDS` 选部署网络内可达的源。

DB 内容页面动态渲染；构建不会冻结 DB 故障文案。构建成功仅代表产物可生成；上线前仍需迁移、内容与运行服务就绪检查。`pnpm release:check` 是只读发布门槛；设置 `RELEASE_BASE_URL` 时还检查目标 `/api/health` 和真实速闻探测。未通过不得切流量。

## 维护边界

- `globals.css`：基础 token、通用组件和阅读正文；`signal.css`：Signal Press 页头、速闻和响应式编排；`reading.css`：阅读清单及分页。
- `AppShell` 统一管理站点页头页脚；已移除无引用的 Header/Footer/HotList。
- 搜索及本机订阅页面不参与索引；sitemap 不用请求时间伪造内容更新时间。
- CI 包含真实 PostgreSQL 集成测试、生产构建、编译产物 smoke 和确定性 Chromium 用户路径回归。浏览器用受控新闻/模型响应，真实上游可达性由独立合成探测验证。
